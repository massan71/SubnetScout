## Fixes

- **ARP and UPnP through the helper.** macOS can deny the app access to the local network even when the permission appears to be on: in that case SubnetScout could not see MACs and UPnP routers. Now, with the helper active, the helper reads the ARP table and looks for UPnP routers. As a system daemon it is not subject to that permission.
- **"Local network blocked" warning.** Without the helper, the Network view tells you when macOS blocks the local network, instead of reporting "no UPnP routers".
- **DHCP.** If no server answers the probe, the result is "no response (inconclusive)" instead of "not run". The probe uses the Mac's real MAC, because many routers ignore random MACs.
- **Unresponsive helper.** Calls to the helper have a timeout: if macOS does not let it start, the app asks you to reinstall it instead of waiting forever.
- **Safer UPnP parsing.** Device descriptions are read without the system XML parser, because this code can now run in the helper with root privileges.
- **Signing.** App and helper are signed with a stable certificate ("SubnetScout Code Signing") and verify each other through that certificate.
- **Diagnostics.** New `SubnetScout --diagnose-network` command to check local network, ARP, helper and UPnP.

## After updating

The signature has changed: with "As administrator" on, click **Reinstall** and approve the helper again in System Settings › General › Login Items & Extensions.
